# 内测反馈问卷设计

## 目标

问卷不追求一个“满意度总分”，而是把一次循证任务拆成可诊断的质量环节：需求理解、临床问题建模、子问题拆分、证据支持、可信度、完整性、可读性和循证规范。另保留一个“结果是否值得等待”的价值判断，用于和后台客观耗时联合分析。

用户不需要评价模型内部的检索步骤。检索次数、失败重试、工具停滞和实际耗时应从后端轨迹自动计算，不能依赖用户回忆。

## 当前问题

以下九项在报告完成后显示，均为必填的 1–5 整数（1 = 完全不符合，5 = 完全符合）：

| 字段 | 用户看到的问题 | 用途 |
| --- | --- | --- |
| `requirement_understanding` | 智能体正确理解了我的需求 | 区分“答得不好”和“从一开始就理解错了” |
| `clinical_interpretation_accuracy` | 智能体对临床问题的理解准确 | 发现人群、干预、对照、结局或决策场景建模错误 |
| `subquestion_decomposition` | 临床子问题拆分合理，覆盖了关键决策点 | 发现研究框架遗漏关键分支或拆分失焦 |
| `evidence_support` | 指南/文献引用足以支持问题的回答 | 检查主张是否有足够、匹配的证据，而不只是“有引用” |
| `report_trustworthiness` | 报告可信，没有明显编造事实或超出证据断言 | 捕捉幻觉、过度外推和证据—结论不一致 |
| `report_completeness` | 报告完整，没有缺少必要的假设验证或边界 | 发现遗漏适用性、冲突、风险或反事实条件 |
| `report_clarity` | 报告清晰、可读，对人类读者友好 | 定位表达、结构和术语造成的理解障碍 |
| `ebm_standard_compliance` | 报告符合循证规范，引用可以回溯 | 检查来源层级、归因、可追溯性和不确定性表达 |
| `time_worth` | 综合报告质量和等待时间，这次使用值得 | 衡量结果价值是否抵消时间成本；客观耗时由轨迹记录 |

另有一个单选题：

> 下次做同类问题，你更愿意用哪个？

选项为“循医”“豆包”“无偏好”“没用过豆包”，分别记录为 `xunyi`、`doubao`、`no_preference`、`not_used`。最后一个选项避免把没有比较基础的人错误计入竞争偏好。

自然语言反馈保持可选，优先提示用户指出具体的结论、引用、遗漏边界或疑似编造位置。这样可以把 1–5 分转化为可执行样本；不提示用户评价某个检索步骤。

问卷默认在每个已完成 query 的报告下展开；用户可点击“暂不填写”关闭本轮问卷。关闭只影响当前 query，不会关闭后续问卷，也不会写入一条空反馈。管理员仍可通过 `EBM_FEEDBACK_ENABLED=0` 在服务端全局关闭反馈接口。

## 分析方式

不要直接平均所有分数。按 `user_id`、问题类型、模型、`run_id` 分层，并把问卷与后台自动记录的 `duration_ms`、工具失败次数、来源复核失败次数、报告是否首次生成等字段连接起来：

- `time_worth` 低而客观耗时高：优先优化超时、并发和检索路径；若耗时不高仍低，则检查结果价值。
- `evidence_support` 或 `ebm_standard_compliance` 低而报告生成成功：检查证据归档、引用映射、来源层级和可追溯性。
- `report_trustworthiness` 低：优先抽取具体主张，核对原文和适用范围，不能用平均分掩盖潜在安全问题。
- `requirement_understanding` 或 `clinical_interpretation_accuracy` 低：优化澄清问题、临床框架和上下文提取，而不是先改写报告。
- 选择“豆包”且上述质量分较高：结合文字反馈记录缺失能力，作为产品差异化线索。
- 选择“没用过豆包”：不参与工具偏好胜负统计，但仍参与本系统质量分析。

问卷记录保存在会话的 `feedback/feedback.jsonl`；每个用户 query 都会在 `trace/queries/{query_id}.json` 留下归属元数据，完整轨迹仍追加保存在 `trace/trajectory.jsonl`，后台分析时通过 `session_id`、`query_id` 和 `run_id` 关联。轨迹中的用户问题标为 `prompt_kind=user_query`，研究范围提醒标为 `prompt_kind=system_reminder`，不会混入用户问题统计。问卷开关由 `EBM_FEEDBACK_ENABLED` 控制。
