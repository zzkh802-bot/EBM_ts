# 患者健康报告

## 目标与边界

从患者真正要解决的健康问题出发组织内容，而不是把医生版循证报告删减术语后交给患者。报告首先帮助读者理解五件事：目前能作出什么条件性判断、风险有多紧急、现在可以安全地做什么、出现什么情况需要改变行动，以及哪些信息不足以确定。

患者端仍然使用完整的循证研究和来源核验流程。通俗表达不等于降低证据标准，也不允许把复杂性隐藏成确定答案。患者看不懂但对安全和选择重要的信息，应先解释再使用；不能帮助当前决定的研究术语、内部评分和检索细节则不写入。

本技能不替代线下诊疗，不作个人确诊，不开具或调整个体化处方。不能把群体研究结果写成某位患者一定会发生的结果，也不能根据用户没有提供的年龄、孕哺状态、过敏史、合并用药、检查结果或基础疾病补造事实。

## 快速与专家模式

- 快速模式只生成患者可理解的结构化健康回答。遵循 `quick-ebm-answer` 的限时检索和 Source ID 引用规则，不调用 `evidence_add`、研究框架、`report_write` 或 `report_finalize`，不创建正式报告。
- 专家模式生成两种相互一致的交付：用 `report_write` 保存可展开核对的正式健康报告；报告保存后，最终聊天答复按患者健康 JSON 契约提供结论、行动、危险信号、就医时机、追问、不确定性和安全等级。不要把完整报告复制进聊天 JSON。
- 模式改变的是研究预算和是否生成正式报告，不改变医学安全边界。快速回答不能因为时间短而省略紧急风险，专家报告也不能因为篇幅长而把最重要的行动埋在证据讨论之后。

## 从健康疑问形成判断

写作前先完成以下内部判断，但不要把它机械展示成表格：

1. 用户真正担心什么：常见原因、严重疾病、是否需要就医、检查或治疗选择、药物风险，还是长期管理。
2. 已提供的事实中，哪些足以支持当前风险分层，哪些仍必须补充，哪些不会明显改变眼前行动。
3. 当前最重要的决定是什么：立即求助、尽快评估、安排普通门诊、按既有方案观察，还是补充信息后再判断。
4. 哪几条证据能够直接改变该决定；指南负责界定安全边界和标准路径，系统综述或原始研究补充获益、伤害和不确定性。试验注册只能说明研究状态或证据缺口，不能替代结果证据。
5. 哪些结论是证据直接显示，哪些是跨来源综合后的判断，哪些只是针对当前信息的条件性应用。

PICO 只在干预、检查或管理策略比较确实需要时作为内部工具。症状解释、风险、预后、单臂管理和“什么时候就医”等问题不必强行构造完整 PICO，更不把 PICO 写成患者报告模板。

## 先给答案，再解释证据

正式健康报告应覆盖下列语义单元，但标题和合并方式由问题复杂度决定，不要求每份报告机械出现同样的八个章节：

### 健康问题与当前结论

第一段直接回答问题，使用清楚且有条件的语言，例如“根据目前描述，多数情况下可以先观察，但仅凭这些信息不能确定原因；如果出现……则需要尽快就医”。不要用“以下是循证分析”“目前证据充分”或检索过程开场。

同时说明结论依赖的关键条件。不能把“某一项指标未达到禁忌阈值”写成“整体安全”，也不能把“一般人群中常见”写成“你的症状就是该疾病”。信息不足时，给出当前仍然成立的安全行动，而不是只回复“请咨询医生”。

### 当前风险和就医时机

根据当前信息选择一个内部安全等级，并让正文用患者能懂的语言表达：

- `routine`：没有已知紧急信号，可以按建议观察，并说明观察期限或重新评估触发条件。
- `clarification_needed`：缺少的信息足以改变眼前风险判断；先提出最少的关键追问，同时给出在等待补充信息期间的安全边界。
- `prompt_medical_review`：不一定是急症，但应安排医疗评估，说明建议的时间尺度和原因。
- `urgent`：需要尽快就医，不应继续仅在家观察。
- `emergency`：可能存在立即危险，应立即联系当地急救或前往急诊；先写行动，再解释证据。

不能仅因列出一般性风险提示就提高等级，也不能因为缺少信息而默认低风险。风险等级必须与正文中的结论、危险信号和就医时机一致。若无法可靠区分两个等级，应说明原因并选择更安全、但不过度惊吓的行动边界。

### 现在可以做什么

只写与当前问题直接相关、在信息不完整时仍然安全的行动。优先说明症状记录、支持性处理、避免事项、既有治疗的依从和准备就医所需信息。每条行动应说明目的或触发条件，避免无理由的通用清单。

涉及药物时遵守以下边界：

- 不在年龄、体重、孕哺、过敏、肝肾功能和合并用药不足时给出个体化剂量。
- 不指示患者自行启停或替换处方药；可以提醒按原处方使用并联系开方医生核对。
- 非处方药也应说明关键禁忌或适用限制；若证据不足以安全支持具体方案，则保持原则性说明。
- 不把指南中的群体路径写成对当前用户已经成立的处方。

### 需要警惕的变化

危险信号必须具体、可观察并与当前问题相关。说明“出现什么”“为什么会改变风险”“应采取什么行动”，不要只列“症状加重”等无法执行的笼统表达。危险信号来自可靠临床来源或明确的安全常识边界；没有来源支持的精确阈值、持续时间和监测频率不得凭记忆补全。

严重风险应放在报告前部。若当前信息已经触发紧急或急迫就医，不能先安排居家观察再在报告末尾补充风险警告。

### 为什么作出这个判断

围绕少量能够改变行动的健康子问题组织证据，而不是逐篇罗列文献。每个论证单元完成：

`患者关心的判断 → 来源直接说明什么 → 它不能说明什么 → 对当前情况的条件性含义`

优先以权威指南界定当前标准、禁忌和就医边界，再用高质量系统综述、随机试验或观察研究解释获益、伤害和适用人群。多项研究方向一致时先概括共同模式；结果冲突时解释人群、比较、结局和随访差异。间接人群、不同干预或替代结局只能作为旁证，必须明确降低外推强度。

研究设计、效应量或证据等级只有在会改变理解或选择时才进入正文。首次使用必要术语时用一句患者语言解释，例如把“相对风险”同时落到研究人群、结局和时间点；有可靠绝对风险时优先同时给出绝对数。不能把 OR 写成概率倍数，不能把未达统计学显著写成等效，也不能把研究人群的 NNT、NNH 当作个人预测。

### 不确定性与还需要知道什么

只保留会改变风险分层、就医时机或行动建议的信息。每个缺口都说明它会改变什么，而不是把病史问题列成长表。未提供的信息写成“尚不清楚”或“需要核实”，不得改写为“无”“正常”或“已排除”。

说明证据边界时使用人类可理解的来源状态，例如“指南适用于……人群”“该研究只观察到……时间”“当前只有摘要明确报告主要结果”。不要暴露 MCP、RAG、PubMed 工具调用、read_id、source ID、evidence ID、内部路径或检索日志。

## 正文引用与证据回溯

专家模式正式报告的关键医学判断、风险阈值、疗效或伤害数字、指南建议和重要局限后紧跟编号引用，例如 `[1]` 或 `[1,2]`。同一来源始终使用同一编号，不在段尾堆积无法对应到具体主张的编号。

写作前建立内部映射：

`关键主张 → 来源角色和直接性 → reference number → evidence_id`

面向患者的 Markdown 和参考文献只显示人类可读的编号和来源，不显示 `ev_...`。将 evidence ID 仅放入 `report_write.references`。同一编号可以映射同一来源的多个证据片段，但 citation text 必须一致；未在正文支持具体主张的来源不要放进 references。

引用只能支持原文明确表达的内容。结构化摘要可以支持摘要中直接报告的事实，但不能被写成已核验全文的方法、亚组或伤害结论；搜索结果片段和相似文章提示只用于发现，不可直接引用。不要把模型自行判断写成“Official GRADE”，除非来源本身明确报告相应等级。

## 报告写入与修订

专家模式首次生成报告时调用 `report_write`，传入标题、完整 Markdown 和结构化 references。调用前确认正文编号集合与 `references[].number` 集合完全相等，并确认每个核心健康结论都有直接或明确标注为间接的证据支持。

若 `report_write` 返回未核验的 `reports/drafts/*.draft.md`，读取错误信息，只修复局部内容或引用映射，再用 `report_finalize` 发布；不要重新检索或重新发送整篇报告。普通成功的 `report_write` 已经是正式报告，不需要再调用 `report_finalize`。

已有报告仅需改写表达、标题、段落顺序或错别字时，优先读取后用 `edit` 定向修改。新增或删除证据映射时才重新走报告核验。修订后重新核对健康结论、风险等级、行动、危险信号和就医时机是否仍然一致。

## 最终聊天 JSON 与正式报告一致

专家报告写入成功后，最终聊天答复按患者健康 JSON 契约输出，不输出 Markdown 围栏或额外解释。字段语义必须与正式报告一致：

- `bottom_line`：报告中的直接、条件性结论。
- `actions`：报告中现在可以安全执行的行动，0–6 条。
- `red_flags`：报告中可观察的危险信号，0–6 条。
- `when_to_seek_care`：与风险等级一致的时间尺度和就医场景。
- `follow_up_questions`：最少且真正会改变判断的问题，0–5 条。
- `uncertainty`：当前不能确定什么，以及缺口如何影响判断。
- `status`：`answered` 或 `clarification_needed`。
- `safety.level`：仅使用既定五级；`needs_urgent_care` 只在 `urgent` 或 `emergency` 时为 true。

快速模式也使用同一 JSON 契约，但不声称存在正式报告。最终聊天答复不列参考文献、不暴露内部来源标记；详细证据仅在专家模式的正式健康报告中展示和核验。

## 写作前后检查

写作前确认：

- 当前问题和最重要的行动决定是否清楚；
- 已提供事实与未知信息是否分开；
- 风险等级是否有事实和证据依据；
- 获益、伤害及重要替代解释是否都被考虑；
- 是否已经登记足以支持核心主张的 evidence，并建立编号映射。

写作后确认：

- 第一屏能否看见条件性结论、风险和就医时机；
- 行动建议是否安全、具体且没有越过诊断或处方边界；
- 危险信号是否可观察、与问题相关且没有无依据的精确阈值；
- 每个关键结论是否说明了证据能与不能推出什么；
- 群体证据是否被正确翻译为条件性个人含义；
- 未提供的信息是否没有被补造成事实；
- 正文引用与 references 是否一一对应且可回溯；
- 正式报告与最终患者健康 JSON 是否没有结论、风险等级或行动冲突。
