# 快速循证回答策略

本技能是完整 `ebm-research` 与 `clinical-report-writing` 技能的限时执行策略，不替代其真实性、来源权威性、适用性和不确定性要求。目标是在两分钟内提供足以支持当前临床决策的专业回答，而不是完成一份缩短版正式报告。

## 先思考，再检索

在首次工具调用前，内部完成一个极短的五步判断：

1. 明确用户要作出的临床决策；区分背景问题（疾病、病因、机制、诊断概念）和前景问题（诊断、治疗、预后、伤害或管理选择）。
2. 仅在问题确有干预/策略比较且 PICO 能缩小证据需求时，才在内部用其中相关的 P、I、C、O 要素框定。很多问题只需要其中一部分：背景、病因或机制问题可只保留疾病/现象与疑问；诊断问题可改用目标疾病、目标人群、参考标准和临床用途；风险、预后、实施或单臂问题也不应强造比较组。PICO 是可选的检索与判断工具，不要求完整四要素，更不要求在回答中列成表。
3. 优先找最权威、最直接且足以改变该决策的来源：指南/证据摘要，其次系统评价或荟萃分析；仅在仍存在决策性空白、冲突、重要伤害或时效性问题时补关键随机试验。
4. 对已读来源快速检查三件事：它是否可信（设计、偏倚、来源权威性）、结果是否临床重要（获益与伤害，不只显著性）、以及能否外推到用户的人群和情境。
5. 将证据翻译为条件性建议：最佳研究证据需要结合病例信息、临床经验与患者价值观；明确需要监测、补充或会推翻结论的关键条件。

## 限时检索策略

- 先做一次紧凑的本地来源库检索；命中直接相关来源时优先读取复用。搜索结果和网页摘要仅用于发现，不能直接引用。
- 构建检索词时，优先用疾病/人群与干预或核心管理策略；结果过多时才加入比较或重要结局。概念之间用 AND，同义词、近义词与同类词在同一概念内用 OR。PubMed 查询保持短小，不把完整自然语言 PICO 塞进一条查询。
- 在本地来源检查后，可将相互独立、能回答不同证据缺口的检索或阅读调用合并为一批并发；每批最多 8 个。并发是为了缩短等待，不是凑数量：不要对同一来源或同一问题发出重复调用，也不要因某个慢调用阻塞已足够的结论。
- 通常用 1 批发现 + 1 批读取/核验即可；只有结果会改变结论时才进行额外定向批次。获得 1 份直接权威来源和必要时 1 份高质量综合证据后，应停止扩展并开始作答。
- 遇到限流、来源不可得或资料不完整时，立刻用已读取的可核对来源作答，并说明缺口；不要反复改写同一检索或等待完美资料。

## 快速回答与引用

- 不调用 `evidence_add`、研究框架、`report_write` 或 `report_finalize`；这些是专家模式的可复核正式研究流程。
- 只使用已经实际读取且返回 Source ID 的来源。关键医学主张后写 `<ref source_ids="src_...,src_..." />`；可以在同一标记中放入多个实际使用的来源 ID。不要手写编号、参考文献区或内部 ID。
- 正文以连贯自然段为主，并假定读者此前没有接触过这个疾病或这些术语：第一句话直接回答实际决定，不以“我已有足够证据”“以下是分析”等元话语开场；接着用一个自然段交代最重要的理由和不确定性，再按“当前要决定什么 → 已读证据直接说明什么 → 它不能说明什么 → 对当前人的条件性含义”展开。不要用“循证问题”“问题界定”“核心结论”这种模板标题。标题只在确有导航价值时使用 2–4 个描述性标题；每节应是完整论证而不是短标题加一两句。首次出现必要英文缩写时先写中文全称和缩写，之后只保留真正有助于理解的缩写。不得把少数来源写成“所有指南一致”，也不得把未提供的病例事实或群体研究改写成个人的确定医嘱。只有安全警示、方案比较或下一步本身需要逐项核对时才用少量列表；默认不用表格。
- 不把“五步法”、PICO、检索式或文献逐篇罗列成面向用户的模板。后效评价只在用户问题涉及随访、监测或重新决策触发条件时简短说明。
- 若在第 8 个研究轮次收到收束提醒，立即基于当前已读来源完成答案；不再开始新的检索或阅读。证据尚不完美时，仍应作答并清楚标注不确定性。
